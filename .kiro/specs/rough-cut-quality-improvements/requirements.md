# Requirements Document

## Introduction

This feature significantly improves the quality and completeness of the rough cut timeline generated by the Rough Cut Agent pipeline. The current pipeline produces a working Cutter-compatible timeline but covers only a fraction of the source script (~56 seconds for a 4:48 news package). The improvements span five areas: (1) voice-over audio generation via Amazon Polly so narration sections are placed on a dedicated audio track, (2) script format detection to distinguish final broadcast scripts from story overviews, (3) precise interview/SOT alignment using timecoded soundbite references in the script matched against transcript data, (4) multi-track timeline assembly with separate tracks for A-roll, B-roll, voice-over audio, and interview/natural sound audio, and (5) model upgrade evaluation to replace Nova Premier with Claude on Bedrock for the Source Material and Timeline Assembly agents. The overarching goal is full script coverage — every section of the script should be systematically matched to source material so the rough cut spans the full package duration.

## Glossary

- **Rough_Cut_Agent**: The existing multi-agent system on AgentCore Runtime that orchestrates Script Analysis, Source Material, and Timeline Assembly sub-agents to produce a rough cut video timeline
- **Script_Analysis_Agent**: The sub-agent that decomposes a story script into broadcast news structure (lead, body, wrap-up, soundbites, interview segments, voice-over sections)
- **Source_Material_Agent**: The sub-agent that searches transcripts and embeddings for video segments matching the script analysis and resolves in/out points
- **Timeline_Assembly_Agent**: The sub-agent that constructs a Mimir sequenceDetails object with video and audio tracks and creates the timeline in Mimir via the Cutter API
- **Polly_Service**: Amazon Polly, the AWS text-to-speech service used to synthesize narrator voice-over audio from script text
- **Staging_Bucket**: The existing S3 bucket (`video-embedding-staging-{account}-{region}`) used for temporary file storage during the pipeline
- **Cutter_API**: The Mimir Cutter timeline API (`PUT /prime/api/v1/timelines/{itemId}`) used to populate timeline items with tracks and clips
- **Broadcast_Script**: A final broadcast news script containing timecodes, SOT markers, VO cues (e.g. `((---PKG---))`, `((nats))`), SUPERS, anchor intro, and reporter sections
- **Story_Overview**: A story description or outline that lacks broadcast formatting, timecodes, and SOT markers — requires narrative construction from available interviews and story details
- **SOT**: Sound On Tape — a pre-recorded interview soundbite referenced in the script with speaker attribution and timecode (e.g. `((05:14)) Selena: "All Palestinians suffered..."`)
- **VO_Section**: A voice-over narration section in the script meant to be read by a narrator over B-roll footage
- **A_Roll**: Primary video footage showing interview subjects or SOT clips, placed on the V1 video track
- **B_Roll**: Supplementary video footage that accompanies VO narration or covers interview subjects, placed on V2+ video tracks
- **Bedrock_Model**: An AI foundation model accessed via Amazon Bedrock, used by the sub-agents for reasoning and structured output generation
- **Nova_Premier**: The `us.amazon.nova-premier-v1:0` model currently used by the Source Material and Timeline Assembly agents
- **Claude_Model**: Anthropic Claude models (Opus or Sonnet) available on Amazon Bedrock, evaluated as a replacement for Nova Premier
- **Mimir_API**: The Mimir REST API at `https://us.mjoll.no` used to retrieve item details, create timeline items, and manage assets
- **Generated_Transcript**: A word-level timed transcript stored in S3 at `transcripts/{itemId}/transcript.json`, produced by the transcript generation pipeline

## Requirements

### Requirement 1: Script Format Detection

**User Story:** As the rough cut pipeline, I want to automatically detect whether the story content is a final broadcast script or a story overview/notes, so that the pipeline can choose the appropriate processing strategy.

#### Acceptance Criteria

1. WHEN the Script_Analysis_Agent receives story content, THE Script_Analysis_Agent SHALL classify the content as either `broadcast_script` or `story_overview` based on the overall structure and detail level of the content
2. THE Script_Analysis_Agent SHALL identify content as `broadcast_script` when the content reads as a producible script with specific narration text, attributed quotes or soundbites, and a clear narrative flow that could be directly read or assembled into a package
3. THE Script_Analysis_Agent SHALL identify content as `story_overview` when the content consists of notes, bullet points, topic summaries, or high-level descriptions that lack specific narration wording or attributed quotes
4. THE Script_Analysis_Agent SHALL include a `scriptFormat` field with value `broadcast_script` or `story_overview` in the ScriptAnalysis output JSON
5. IF the content is classified as `story_overview`, THEN THE Script_Analysis_Agent SHALL construct a narrative structure from available interview references, story details, and editorial notes to produce a synthetic script outline suitable for timeline assembly

### Requirement 2: Broadcast Script Parsing

**User Story:** As the rough cut pipeline, I want the Script Analysis Agent to parse final broadcast scripts into their constituent sections with timecodes preserved, so that downstream agents can match each section to source material.

#### Acceptance Criteria

1. WHEN the content is classified as `broadcast_script`, THE Script_Analysis_Agent SHALL parse the script into an ordered list of sections, each tagged with a section type from: `anchor_intro`, `reporter_live`, `pkg_vo`, `pkg_sot`, `pkg_nats`, `live_tag`, `anchor_qa`, or `super`
2. THE Script_Analysis_Agent SHALL preserve timecoded SOT references (e.g. `((05:14)) Selena: "All Palestinians suffered..."`) as structured objects containing the timecode in seconds, speaker name, and quoted content
3. THE Script_Analysis_Agent SHALL preserve VO narration text for each `pkg_vo` section as the exact script text to be synthesized as voice-over audio
4. THE Script_Analysis_Agent SHALL output the parsed sections in script order so that the timeline can be assembled sequentially
5. THE Script_Analysis_Agent SHALL include a `parsedSections` array in the ScriptAnalysis output JSON, where each entry contains `sectionType`, `content`, `orderIndex`, and optional `timecodeSeconds`, `speaker`, and `quotedText` fields

### Requirement 3: Voice-Over Audio Generation

**User Story:** As the rough cut pipeline, I want to generate narrator voice-over audio from VO script text using Amazon Polly, so that narration sections are represented as audio clips on the timeline.

#### Acceptance Criteria

1. WHEN the Script_Analysis_Agent identifies one or more `pkg_vo` sections, THE Rough_Cut_Agent SHALL synthesize each VO section's text into an audio file using the Polly_Service
2. THE Rough_Cut_Agent SHALL call the Polly_Service `SynthesizeSpeech` API with `OutputFormat` set to `mp3`, `Engine` set to `neural`, and `VoiceId` set to a configurable news-style voice (default: `Matthew`)
3. THE Rough_Cut_Agent SHALL store each synthesized audio file in the Staging_Bucket at the key `voiceover/{storyId}/{sectionIndex}.mp3`
4. THE Rough_Cut_Agent SHALL determine the duration of each synthesized audio file in milliseconds and include the duration, S3 URI, and section index in the voice-over metadata passed to the Timeline_Assembly_Agent
5. IF the Polly_Service returns an error for a VO section, THEN THE Rough_Cut_Agent SHALL log the error, skip the failed VO section, and continue processing remaining VO sections
6. THE Rough_Cut_Agent SHALL expose a `generate_voiceover` tool that accepts script text and a section index, calls the Polly_Service, stores the result in S3, and returns the S3 URI and duration

### Requirement 4: Interview and SOT Timecode Alignment

**User Story:** As the Source Material Agent, I want to match timecoded SOT references in the script to exact positions in the source video transcripts, so that interview clips are placed at precise in/out points on the timeline.

#### Acceptance Criteria

1. WHEN the script contains a timecoded SOT reference (e.g. `((05:14)) Selena: "All Palestinians suffered..."`), THE Source_Material_Agent SHALL convert the timecode to seconds and search the generated transcripts for the matching speaker and content within a 30-second window centered on the timecode
2. THE Source_Material_Agent SHALL use the `get_word_timing` tool to retrieve word-level timing data for the matching time range and resolve the exact `inPointMs` and `outPointMs` for the soundbite
3. THE Source_Material_Agent SHALL match the quoted text from the SOT reference against the transcript text using substring matching, aligning the in-point to the first matching word and the out-point to the last matching word plus a 500ms pad
4. IF the Source_Material_Agent cannot find a transcript match for a timecoded SOT reference within the 30-second window, THEN THE Source_Material_Agent SHALL expand the search to the full transcript of the referenced item and report the match confidence as `low`
5. THE Source_Material_Agent SHALL include a `matchConfidence` field (`high`, `medium`, or `low`) for each SOT candidate based on the quality of the timecode and text alignment

### Requirement 5: Full Script Coverage

**User Story:** As the rough cut pipeline, I want every section of the script to be systematically matched to source material, so that the rough cut covers the full duration of the news package.

#### Acceptance Criteria

1. THE Source_Material_Agent SHALL process every section in the `parsedSections` array from the Script_Analysis_Agent output, producing at least one candidate or a gap entry for each section
2. THE Source_Material_Agent SHALL report a `coveragePercentage` field in the output indicating the fraction of script sections that have at least one matched candidate
3. WHEN the `coveragePercentage` is below 80%, THE Source_Material_Agent SHALL perform a second pass using broader semantic search queries (top_k increased to 20) for unmatched sections
4. THE Timeline_Assembly_Agent SHALL place clips for every matched section in script order, producing a timeline whose total duration approximates the expected package duration (within 20% of the sum of all section durations)
5. IF a script section has no matched candidates after both passes, THEN THE Timeline_Assembly_Agent SHALL insert a placeholder gap of estimated duration on the timeline and record the gap in the output summary

### Requirement 6: Multi-Track Timeline Assembly

**User Story:** As the Timeline Assembly Agent, I want to build a multi-track timeline with separate video and audio tracks for A-roll, B-roll, voice-over, and interview audio, so that the rough cut follows broadcast editing conventions.

#### Acceptance Criteria

1. THE Timeline_Assembly_Agent SHALL construct a timeline with a minimum of four tracks: V1 (A-roll / interview video), V2 (B-roll / cover footage), A1 (voice-over narration audio), and A2 (interview and natural sound audio)
2. THE Timeline_Assembly_Agent SHALL place SOT/interview video clips on the V1 track and VO-accompanying B-roll clips on the V2 track
3. THE Timeline_Assembly_Agent SHALL place synthesized voice-over audio clips (from Polly) on the A1 track, aligned to the timeline position of the corresponding VO script section
4. THE Timeline_Assembly_Agent SHALL place interview audio and natural sound clips on the A2 track, aligned to the corresponding V1 video clips
5. THE Timeline_Assembly_Agent SHALL ensure clips on the same track do not overlap: for each track, clips sorted by `start` position SHALL satisfy `clips[i].end <= clips[i+1].start`
6. THE Timeline_Assembly_Agent SHALL update the `create_timeline` tool to support multiple video tracks and audio tracks with source references for both video-with-audio and audio-only clip types
7. WHEN a B-roll clip on V2 accompanies a VO section, THE Timeline_Assembly_Agent SHALL align the B-roll clip's start and end positions to match the corresponding voice-over audio clip on A1

### Requirement 7: Voice-Over Audio as Timeline Audio Source

**User Story:** As the timeline creation tool, I want to reference Polly-generated audio files stored in S3 as audio-only source clips in the Cutter timeline payload, so that voice-over narration plays on the timeline.

#### Acceptance Criteria

1. THE `create_timeline` tool SHALL support an `audio-only` source reference type in addition to the existing `video-with-audio` type
2. WHEN an audio-only source reference is provided, THE `create_timeline` tool SHALL create an `itemRef` with `type` set to `audio` and `nAudioChannels` set to 1
3. THE `create_timeline` tool SHALL create a `sourceRef` for audio-only clips with `type` set to `audio-only`, referencing the Polly-generated audio file's Mimir item ID or S3-backed reference
4. IF the Polly-generated audio file needs to be registered as a Mimir item before timeline creation, THEN THE Rough_Cut_Agent SHALL create a Mimir audio item for each voice-over file and use the resulting item ID in the timeline payload

### Requirement 8: Model Upgrade for Source Material and Timeline Assembly Agents

**User Story:** As the rough cut pipeline, I want to evaluate and optionally switch the Source Material and Timeline Assembly agents from Nova Premier to Claude (Opus or Sonnet) on Bedrock, so that the agents produce more accurate structured output and follow complex multi-step instructions reliably.

#### Acceptance Criteria

1. THE Rough_Cut_Agent SHALL support a configurable `model_id` parameter for the Source_Material_Agent and Timeline_Assembly_Agent, defaulting to the current `us.amazon.nova-premier-v1:0`
2. THE Rough_Cut_Agent SHALL accept model configuration via an environment variable `AGENT_MODEL_ID` that overrides the default model for both the Source_Material_Agent and the Timeline_Assembly_Agent
3. WHEN `AGENT_MODEL_ID` is set to a Claude model identifier (e.g. `us.anthropic.claude-sonnet-4-20250514-v1:0`), THE Rough_Cut_Agent SHALL instantiate the BedrockModel with the specified model ID and set `max_tokens` to 16000 to accommodate Claude's output requirements
4. THE Rough_Cut_Agent SHALL validate that the configured model ID is accessible on Bedrock before starting the pipeline, and IF the model is not accessible, THEN THE Rough_Cut_Agent SHALL fall back to the default Nova Premier model and log a warning
5. THE Source_Material_Agent and Timeline_Assembly_Agent SHALL produce identical output JSON schemas regardless of which model is configured, ensuring downstream compatibility

### Requirement 9: Polly Voice-Over Infrastructure

**User Story:** As a system operator, I want the Rough Cut Agent deployed with Amazon Polly permissions and voice-over storage configuration, so that the agent can synthesize and store voice-over audio.

#### Acceptance Criteria

1. THE AgentCore execution role for the Rough_Cut_Agent SHALL have IAM permissions to call `polly:SynthesizeSpeech` on all Polly resources
2. THE AgentCore execution role for the Rough_Cut_Agent SHALL have IAM permissions to write to the Staging_Bucket under the `voiceover/` prefix
3. THE Rough_Cut_Agent SHALL receive the Staging_Bucket name as the `TRANSCRIPT_STAGING_BUCKET` environment variable (reusing the existing variable)
4. THE Rough_Cut_Agent SHALL receive a configurable Polly voice ID via the `POLLY_VOICE_ID` environment variable, defaulting to `Matthew` when not set

### Requirement 10: Script Section Duration Estimation

**User Story:** As the Timeline Assembly Agent, I want accurate duration estimates for each script section, so that the timeline can be assembled with correct timing and full package coverage.

#### Acceptance Criteria

1. THE Script_Analysis_Agent SHALL estimate the duration of each parsed section in milliseconds based on section type: VO sections estimated at 150 words per minute, SOT sections estimated from the timecoded duration or quoted text length, and transition cues (nats) estimated at 3000ms
2. THE Script_Analysis_Agent SHALL include an `estimatedDurationMs` field for each entry in the `parsedSections` array
3. THE Script_Analysis_Agent SHALL compute and include a `totalEstimatedDurationMs` field representing the sum of all section durations, providing the expected package length
4. WHEN a SOT reference includes both a start timecode and an end timecode or a duration indicator, THE Script_Analysis_Agent SHALL use the explicit duration rather than estimating from word count

### Requirement 11: Voice-Over Audio Upload to Mimir

**User Story:** As the rough cut pipeline, I want synthesized voice-over audio files uploaded to Mimir as audio items, so that the Cutter timeline can reference them as proper source clips.

#### Acceptance Criteria

1. WHEN a voice-over audio file is synthesized and stored in S3, THE Rough_Cut_Agent SHALL create a Mimir audio item for the file using the Mimir_API `POST /api/v1/items` endpoint with `itemType` set to `audio`
2. THE Rough_Cut_Agent SHALL set the Mimir audio item title to `"{storyTitle} - VO {sectionIndex}"` for identification
3. THE Rough_Cut_Agent SHALL associate the created Mimir audio item as a child of the timeline item by including the audio item ID in the `parentItemIds` when creating the timeline
4. IF the Mimir audio item creation fails, THEN THE Rough_Cut_Agent SHALL log the error and exclude the voice-over clip from the timeline without failing the entire pipeline

### Requirement 12: Enhanced Source Material Output for Multi-Track Assembly

**User Story:** As the Source Material Agent, I want to tag each candidate segment with its intended track placement, so that the Timeline Assembly Agent can correctly distribute clips across multiple tracks.

#### Acceptance Criteria

1. THE Source_Material_Agent SHALL include a `trackPlacement` field for each candidate segment with value `v1_aroll` for interview/SOT clips or `v2_broll` for B-roll/cover footage clips
2. THE Source_Material_Agent SHALL include an `audioType` field for each candidate segment with value `interview` for SOT/interview audio, `nats` for natural sound, or `none` for clips that rely on voice-over narration
3. WHEN a candidate segment is matched to a `pkg_vo` script section, THE Source_Material_Agent SHALL tag the candidate with `trackPlacement: v2_broll` and `audioType: none`
4. WHEN a candidate segment is matched to a `pkg_sot` script section, THE Source_Material_Agent SHALL tag the candidate with `trackPlacement: v1_aroll` and `audioType: interview`

### Requirement 13: Reporter-Provided Voice-Over Detection

**User Story:** As the rough cut pipeline, I want to detect when a reporter-provided voice-over audio or video clip exists among the story assets, so that the pipeline uses the reporter's actual narration instead of generating synthetic Polly audio.

#### Acceptance Criteria

1. WHEN the Source_Material_Agent processes VO script sections, THE Source_Material_Agent SHALL first search the generated transcripts for content that matches the VO narration text before falling back to Polly synthesis
2. THE Source_Material_Agent SHALL identify a source asset as a reporter-provided VO track when the transcript content matches the VO script text with at least 70% word overlap and the asset is either an audio-only item (`itemType: audio`) or a video item whose transcript consists primarily of a single speaker reading narration
3. IF a reporter-provided VO track is found for a VO section, THEN THE Timeline_Assembly_Agent SHALL use the reporter's audio (extracted from the matched asset) on the A1 voice-over track instead of generating Polly audio
4. IF a reporter-provided VO track is a video item, THEN THE Timeline_Assembly_Agent SHALL place the video on V1 as A-roll and the audio on A1 as voice-over, with B-roll on V2 if available
5. THE Source_Material_Agent SHALL include a `voiceoverSource` field for each VO section candidate with value `reporter_provided` when matched to an existing asset or `polly_generated` when no match is found and Polly synthesis is required
6. THE Rough_Cut_Agent SHALL only invoke the `generate_voiceover` Polly tool for VO sections where no reporter-provided VO track was identified
